# Nexus Pay — Deployment Guide

## Overview

This guide covers how to deploy Nexus Pay's backend infrastructure and frontend. All commands are derived from the actual deployment scripts and configuration files in the repository. Do not invent steps.

> **Important:** Nexus Pay requires AWS credentials and an AWS account with access to Amazon Bedrock AgentCore Payments (currently in public preview). Do not attempt deployment without verifying access.

- Amazon Bedrock AgentCore Payments access (public preview — may require allowlist)
- Amazon Bedrock model access enabled:

- Wallet provider credentials (see [docs/credentials.md](credentials.md))
- Testnet USDC from [Circle Faucet](https://faucet.circle.com/) on Base Sepolia or Solana Devnet

## Environment Setup

### 1. Clone the Repository

```bash
git clone https://github.com/lakshya0101/Nexus-Pay.git
cd Nexus-Pay
```

### 2. Configure Environment Variables

```bash
cp .env-sample .env
```

Open `.env` and fill in:

| Variable | Required | Source |
|---|---|---|
| `AWS_REGION` | Yes | Your target AWS region (e.g. `us-east-1`) |
| `AWS_ACCOUNT_ID` | Yes | Your 12-digit AWS account ID |
| `TEXT_MODEL_ID` | Optional | Default: `us.anthropic.claude-sonnet-4-6` |
| `VOICE_MODEL_ID` | Optional | Default: `amazon.nova-2-sonic-v1:0` |
| `USDC_CONTRACT` | Optional | Default: Base Sepolia USDC (already in sample) |
| `SOLANA_USDC_MINT` | Optional | Default: Devnet USDC mint (already in sample) |
| `STORE_FROM_EMAIL` | Optional | SES-verified email for order confirmations |

The following variables are **auto-populated** by `npm run setup:backend`:
- `COGNITO_USER_POOL_ID`
- `COGNITO_CLIENT_ID`
- `API_URL`
- `PAYMENT_MANAGER_ROLE_ARN`
- `MEMORY_ID`
- `SELLER_API_URL`
- `STOREFRONT_API_URL`
- `VITE_API_URL`
- `VITE_COGNITO_USER_POOL_ID`
- `VITE_COGNITO_CLIENT_ID`

Do not commit `.env` to source control.

### 3. Configure AWS Credentials

```bash
aws configure
```

Or use environment variables / IAM roles / AWS SSO as appropriate for your environment.

> Do not share your AWS credentials with anyone. Do not commit them to the repository.

## Backend Deployment

### Deploy the Full Stack

```bash
npm run setup:backend
```

This script (`test/integration/setup_backend.sh`) performs:
1. Installs backend dependencies (`cd backend && npm install`)
2. Installs shared Lambda layer dependencies (pip into `lambdas/shared/python/`)
3. Bootstraps CDK (`cdk bootstrap`)
4. Deploys the `PaymentAgentStack` via `cdk deploy`
5. Captures CDK stack outputs and injects them into `.env`
6. Triggers CodeBuild to build the ARM64 Docker image and push to ECR
7. Waits for the AgentCore Runtime to become active

**Expected duration:** 15–30 minutes (first deploy; subsequent deploys are faster)

**What gets created:**
- Cognito User Pool + client + groups
- HTTP API Gateway (Cognito-authed main API)
- HTTP API Gateway (x402 seller API, no auth)
- 7 Lambda functions (Python 3.13)
- 2 Lambda functions (Node.js 22, ARM64)
- DynamoDB tables (products, orders, seller config)
- S3 buckets (media, library, assets)
- ECR repository
- CodeBuild project
- AgentCore Memory resource
- AgentCore Runtime resource
- IAM roles and policies
- Secrets Manager secret (admin credentials)

### Retrieve Admin Credentials

The admin login password is auto-generated by CloudFormation and stored in Secrets Manager. After deployment:

```bash
aws secretsmanager get-secret-value \
  --secret-id <AdminCredentialsSecretName from CDK outputs> \
  --query SecretString \
  --output text
```

The admin username is `demo@agentcore-payments.dev`.

## Frontend Deployment

### Deploy to AWS Amplify

```bash
npm run setup:amplify
```

This script (`test/integration/setup_amplify.sh`) performs:
1. Reads frontend configuration from `.env` (populated by `setup:backend`)
2. Creates an Amplify app
3. Configures build settings from `amplify.yml`
4. Deploys the frontend SPA to a public HTTPS URL

**Expected duration:** 5–10 minutes

### Alternative: Run Frontend Locally

For development or demo without Amplify:

```bash
cd frontend
npm install
```

Create `frontend/.env.local` with:
```
VITE_API_URL=<your API_URL from .env>
VITE_COGNITO_USER_POOL_ID=<your COGNITO_USER_POOL_ID>
VITE_COGNITO_CLIENT_ID=<your COGNITO_CLIENT_ID>
VITE_USDC_CONTRACT=0x036CbD53842c5426634e7929541eC2318f3dCF7e
VITE_BASE_SEPOLIA_RPC=https://sepolia.base.org
VITE_SOLANA_DEVNET_RPC=https://api.devnet.solana.com
VITE_SOLANA_USDC_MINT=4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU
# Optional — only needed for Stripe/Privy instruments:
# VITE_PRIVY_APP_ID=
# VITE_PRIVY_SIGNER_ID=
```

Then:

```bash
cd frontend
npm run build
```

Output: `frontend/dist/` — ready to serve from any static host.

## Post-Deployment Setup

After deploying the infrastructure, an admin user must configure the payment infrastructure through the admin UI:

### 1. Create a Credential Provider

1. Sign in as admin (`demo@agentcore-payments.dev`)
2. Navigate to **Credential Providers**
3. Create a provider with either:
   - **Coinbase CDP** — API Key ID, API Key Secret, Wallet Secret
   - **Stripe/Privy** — App ID, App Secret, Authorization Key ID, Authorization Private Key
4. See [docs/credentials.md](credentials.md) for how to obtain these values

### 2. Create a Payment Manager

1. Navigate to **Payment Managers**
2. Create a manager — this becomes the central payment authority

### 3. Create a Payment Connector

1. Navigate to **Payment Connectors**
2. Link the manager to the credential provider

### 4. Configure the Seller

1. Navigate to **Seller Setup**
2. Enter the seller credential provider details
3. This provisions the seller's payout wallet for the storefront and image-gen seller

### 5. Create a User Account

1. Sign up as a regular user from the Login page
2. Verify the email
3. (The post-confirmation Cognito trigger auto-assigns the user to the `user` group)

### 6. Connect a User Wallet

1. Sign in as the regular user
2. Navigate to **Instruments** (Wallets)
3. Create a new instrument using the manager + connector from above
4. For Coinbase CDP: complete the email OTP + delegation grant via Coinbase Wallet Hub
5. For Stripe/Privy: click **Add Signer** and complete the Privy email OTP

### 7. Fund the Wallet

1. Get the wallet address from the Instruments page
2. Visit [Circle Faucet](https://faucet.circle.com/)
3. Request testnet USDC on Base Sepolia or Solana Devnet

### 8. Create a Payment Session

1. Navigate to **Sessions**
2. Create a session with a `maxSpendAmount` (e.g., 5.00 USDC) and expiry window
3. The agent will use this session for all transactions

## Vercel / Netlify Deployment (Frontend Only)

The frontend can be deployed to Vercel or Netlify as a static SPA after building:

### Vercel

```bash
cd frontend
npx vercel --prod
```

Set environment variables in the Vercel dashboard (same `VITE_*` variables as above).

Build settings:
- **Framework:** Vite
- **Build Command:** `npm run build`
- **Output Directory:** `dist`
- **Root Directory:** `frontend`

### Netlify

```bash
cd frontend
npm run build
npx netlify deploy --prod --dir=dist
```

Or connect the repository in the Netlify dashboard with:
- **Base directory:** `frontend`
- **Build command:** `npm run build`
- **Publish directory:** `frontend/dist`

> **Note:** Frontend-only deployment will render the UI but all API calls will fail without the AWS backend deployed and env vars configured.

## Tear Down

To remove all deployed AWS resources:

```bash
npm run cleanup
```

> **Warning:** This deletes all DynamoDB tables, S3 buckets, Lambda functions, the AgentCore Runtime, and the Cognito user pool. All data will be permanently lost. Confirm with your team before running.

## Demo Mode Limitations

When presenting Nexus Pay without a fully deployed backend:

- The frontend will load and render all pages
- All API calls will fail (no backend means no data)
- No real payments or sessions are possible
- There is no built-in offline/mock mode

**Recommended demo approach:** Deploy the full backend before the hackathon presentation. Use testnet USDC — no real funds are involved.

Always be explicit during the demo:
> "All payments shown are testnet USDC transactions. No real funds are transferred."

## Security Notes

- Never commit `.env` to source control
- Never share AWS credentials, API keys, private keys, or wallet seed phrases
- The admin password is stored in Secrets Manager — retrieve it securely after deployment
- All S3 buckets enforce HTTPS and block public access
- Wallet credentials are stored in Secrets Manager under KMS encryption — the agent never sees raw keys
